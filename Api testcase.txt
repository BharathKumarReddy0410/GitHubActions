Scenario 1: User Registration API

A web application provides a User Registration API (POST /api/register) that allows new users to create an account. The request contains four fields: username, email, password, and age. The username field is mandatory, should contain between 5 and 20 characters, and must be unique across all users. The email field is mandatory, should follow a valid email format, and should also be unique. The password field is mandatory and must contain at least 8 characters, including one uppercase letter, one lowercase letter, one digit, and one special character. The age field is optional, but if provided, its value should be between 18 and 60 years inclusive. On successful registration, the API returns a success message along with the generated user ID. If validation fails or a duplicate username or email already exists, an appropriate error message should be returned. The API should also handle invalid inputs, null values, special characters, SQL injection attempts, and unusually large input values gracefully without affecting application security or performance.

Scenario 2: Login API

A web application exposes a Login API (POST /api/login) that authenticates registered users. The request requires an email and a password. Both fields are mandatory. The email must belong to a registered user, and the password should exactly match the stored password, including case sensitivity. If invalid credentials are entered, an error message should be returned. The application should lock the account after five consecutive failed login attempts, and the user should not be able to log in again for the next 30 minutes. After the lock duration expires, the user should be able to log in successfully using valid credentials. Upon successful authentication, the API generates and returns a JWT token. The system should properly handle scenarios such as blank fields, null values, invalid email formats, SQL injection attempts, leading and trailing spaces, extremely long input values, and multiple concurrent login requests. The generated token should be unique, valid, and securely returned in the response.
